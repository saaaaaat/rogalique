# Дизайн-документ игры "Roguelike 2D"

## 1. Общее описание игры
- **Жанр:** 2D  Roguelike / Survival.
- **Цель игры:** Игрок должен исследовать процедурно генерируемый лабиринт,найти в нем первую половину ключа, найти портал в комнату босса, выжить в схватке с боссом (получить вторую половину ключа) и добраться до выхода.
- **Главный герой:** Абстрактный персонаж (синий круг), обладающий запасом здоровья, брони и выносливости (стамины).
- **Враги:** 
  - *Chaser (Преследователь)* — использует алгоритм поиска пути A*, наносит контактный урон.
  - *Exploder (Подрывник)* — взрывается при приближении игрока, нанося большой урон по площади.
  - *Boss (Босс)* — имеет 2 фазы (лазерные атаки и радиальные волны пуль). Неуязвим, цель игрока — выжить в течение 60 секунд.
- **Что нужно делать:** Перемещаться по лабиринту, собирать предметы (зелья, ключи, меч), использовать стамину для бега, уклоняться от атак и следить за инвентарем.

## 2. Список механик и фич
**Базовые механики:**
- Движение по WASD/стрелкам, спринт (с расходом стамины).
- Дискретная камера (перемещение по секторам-блокам лабиринта).
- Система здоровья и брони, система инвентаря (клавиша 1).
- Взаимодействие с предметами (подбор, использование).

**Добавлено самостоятельно (в рамках направления):**
- **Собственный игровой движок:** Реализована компонентная архитектура (ECS) на C++, системы рендера, логирования и управления ресурсами.
- **Процедурная генерация:** Алгоритм DFS (Recursive Backtracker) для создания 6 связанных между собой блоков лабиринта.
- **Искусственный интеллект:** Реализация алгоритма поиска кратчайшего пути A* (A-star) для врагов.
- **Босс-файт:** Собственная система триггеров лазерных ловушек и паттернов стрельбы.
- **Инвентарь и лут:** Механики невидимости, создания клона-приманки, атаки мечом.

## 3. Оценка фич по сложности (в сторипоинтах)
*Оценка проводилась по шкале Фибоначчи (1, 2, 3, 5, 8, 13).*

- **Ядро движка (ECS, Трансформы, Рендер):** 13 SP
- **Процедурная генерация лабиринта (DFS):** 8 SP
- **ИИ врагов (A* pathfinding, коллизии):** 8 SP
- **Босс-файт (2 фазы, лазеры, пули):** 13 SP
- **Инвентарь и предметы (логика, UI):** 3 SP
- **Управление игроком (движение, стамина):** 5 SP
- **Настройка Git, документация, релизы:** 3 SP

*Общая сложность проекта: ~53 Story Points.*

## 4. Таймлайн разработки по спринтам (примерный)
- **Спринт 1 (База):** Настройка проекта, написание ядра движка (GameObject, Component, Transform, RenderSystem). Сборка простого лабиринта.
- **Спринт 2 (Игрок, Мир, Враги, Лут):** Реализация процедурной генерации (DFS), управление игроком, стамина, камера. Написание ИИ на A*, добавление преследователя и бомб. Создание инвентаря и предметов.
- **Спринт 3 (Босс и Полировка):** Создание арены босса, паттернов атак (лазеры, пули). Добавление HUD, экранов смерти/победы.
- **Спринт 5 (Релиз):** Балансировка, исправление багов, написание документации, чистка кода и подготовка Release-сборки.

## 5. Работа с Git (ветки и MR)
В процессе разработки использовалась следующая структура веток:
- `main` — стабильная ветка, содержащая только релизный код.
- `diplom` — крупная фича-ветка, в которой велась основная разработка (босс, новые механики, расширение лабиринта).
- `refactor/cleanup` — ветка для очистки проекта от устаревшего кода (удаление наследия старых прототипов, мертвого кода).
- **Merge Requests (MR):** Были использованы для безопасного слияния готовых фич и документации (например, `feature/readme`) в ветку `main` без риска сломать рабочую сборку.
